更快的迷宫：深度优先 vs 广度优先

📋 客户要求 S6 你用的是左手扶墙法——它一定能走到宝箱，但不一定是最短路线。客户现在要你算出最短路线，并且要你亲手实现两种搜索算法，比一比谁更聪明：
  • 深度优先 DFS：一条路走到黑，撞墙才回头换一条。
  • 广度优先 BFS：一圈一圈往外扩，先找到的一定是最短的。
关键工具：measure() 在迷宫任何位置都能返回宝箱坐标——这就是"目标在哪"的信息来源。
必须用 measure() 拿宝箱坐标 必须用 can_move() 探墙 必须用队列或栈存待访问的格子 必须记录已访问过的格子 必须输出 BFS 的最短步数
💡 思路拆解（先自己读一遍再看）

核心概念 · "访问过"标记：两种算法都必须记住哪些格子已经看过了，不然会在死胡同里来回转。
用字典记（S4 学过）：visited[(x, y)] = True。

DFS · 深度优先：用栈（或者干脆递归）。规则是"走到最深处，撞墙就退回来换一条路"。
特点：可能先走很远才发现没路；不适合求最短路。

BFS · 广度优先：用队列（先进先出）。规则是"一圈一圈往外扩，先把离起点近的都看一遍"。
特点：第一次碰到宝箱时，走的步数就是最少的。

为什么 BFS 求最短路？因为它按步数分层：第 0 层是起点，第 1 层是走一步能到的地方……所以它永远先搜步数少的。找到宝箱时，前面所有更短的路线都搜过了。
DFS 不分层，它可能一头扎进最长的那条路，所以找到的不一定最短。

游戏里怎么探测？can_move(dir) 告诉你这个方向能不能走（不消耗步数）。measure() 在任何格子都能告诉你宝箱坐标。
所以：不用真的一格格走，可以在"想"的时候就把路径算出来，再真正走一遍。

🔧 常见报错 · 卡住了先看这里

死循环 → 忘了标记已访问。同一个格子被反复加进队列，永远停不下来。

IndexError → 算邻居坐标时越界了。四个方向要分别判断是否在 0 ~ size-1 之间。

measure() 返回 None → 你不在迷宫里。measure() 只在迷宫里有效。先 plant(Entities.Bush) + use_item(Items.Weird_Substance, n) 把迷宫变出来。

BFS 步数比左手扶墙还多 → 检查一下：你算的步数是"搜索时想的步数"还是"实际走的步数"？搜索路径里每一步都要用 can_move 验证过才能走。

收不到金币 → 必须站到宝箱上再 harvest()。measure() 给你坐标，但不会自动走过去。

📌 老师注记这一单是整个课程里思维难度最高的一单，但也是最有价值的一单——DFS 和 BFS 是计算机专业所有算法的地基。
教学节奏建议：先只让做 BFS（目标明确：求最短步数），DFS 作为对比演示即可，不必强求两都写出来。
学生最容易卡住的地方是忘了 visited，可以先让他们故意不加 visited跑一次，亲眼看到死循环，印象最深。
