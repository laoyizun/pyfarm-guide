特殊订单 2

goto(x, y)：自己造一个"走到指定位置"

📋 客户要求 游戏自带的 API 里没有"一步走到 (x, y)"这种命令——只有一步一步的 move()。
客户要你自己写一个 goto(x, y)：不管无人机现在在哪，都能把它准确地开到指定格子。写好之后，整个农场脚本都能用上它——这叫函数。
必须自己定义 def goto(x, y) 必须分横竖两步 必须用 while 判断到没到 必须在别处调用它 必须知道 import 是什么
💡 思路拆解（先自己读一遍再看）

为什么要分两步？如果写成"先看 x 还差几格就走几格，再看 y 还差几格就走几格"这种混着走的逻辑，很容易走出田的边界。先横着走到目标列（此时 y 不变），再竖着走到目标行——每一步都 guaranteed 在田里。

函数的三要素：
① 参数 x, y——"要去哪"，调用时才决定；
② 返回值——走到就到了，可以 return True；走不到（被墙挡住）就 return False；
③ 调用——goto(2, 3) 就是"用这个能力"。

关于 import：在真实 Python 里，你想用别人写好的功能会写 import math——把工具箱搬进来。
这个游戏里也有 import：科技树里有一个「导入」节点（解锁要 80 根胡萝卜），游戏内文档给的写法是：
import other_file 然后 other_file.function()。
也就是：只能 import 自己的代码文件（游戏里另开的代码窗口就是"文件"），不能 import 标准库。
所以本题的正确姿势是：把 goto 单独写在一个文件里，主文件 import 它，再通过"文件名.函数名"调用。
这就是"函数"的意义：写一次，用无数次；这就是 import 的意义：写好的工具还能拆成独立文件，重复利用。

# 文件 A（另一个代码窗口，文件名就叫 tools）
def goto(x, y):
    while get_pos_x() != x:
        move(East) if get_pos_x() < x else move(West)
    while get_pos_y() != y:
        move(North) if get_pos_y() < y else move(South)

# 文件 B（主程序）
import tools                # 把工具箱搬进来
tools.goto(2, 3)            # 用工具：文件名.函数名()
🔧 常见报错 · 卡住了先看这里

一直转圈停不下来 → while 的条件写错了。判断条件要同时看两个坐标：while get_pos_x() != x or get_pos_y() != y:（用 or，不用 and——只要还有一个没到就得继续走）。

走到一半卡住不动 → 田里有墙或障碍，move() 失败了但循环还在转。让 move() 的返回值参与判断，走不动就退出。

走过头了 → 移动前先比较大小，别无脑往一个方向冲。if get_pos_x() < x: move(East) else: move(West)。

写 import 报错 → 还没解锁「导入」这个科技。去科技树里找到它（要 80 根胡萝卜），解锁后再写。

import 报"找不到文件" → 文件名对不上。import tools 里的 tools 要和另一个代码窗口里保存的文件名完全一致（不写 .py 后缀）。

调用时报"没有这个属性" → 记成 goto(2, 3) 了。import 进来之后要写成 tools.goto(2, 3)——带上文件名。

import 了但还是报错 → 游戏里 import 的规则和真实 Python 不完全一样：只能导入自己开的代码文件，不能 import 任何标准库（import math 是无效的）。

  • 加返回值：让 goto 走到了就返回 True，这样能写成 if goto(2, 3): harvest() 吗？
  • 改写题：把 goto(x, y) 改成"能走多远走多远，但不能穿过墙"——你会怎么改？
  • 拆文件：把 goto 单独放一个代码窗口，主文件用 import 把它搬进来。
